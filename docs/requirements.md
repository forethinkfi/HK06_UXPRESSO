# 요구사항 요약

원문 요구사항 3건을 한 곳에 정리한 요약본입니다. 문제 가설은 현장 리서치와 사용성 테스트로 검증해야 합니다.

## 1. 기획 PRD (Ver. 2.0)
- **핵심 가치** Fast · Easy · Self / **핵심 KPI** 독립 주문 완료율
- **문제** 피크타임에 직원이 제조에 집중하는 동안, 키오스크 사용 중 막힌 고객이 스스로 해결하지 못해 주문 지연·직원 부담이 생김
- **전략** FAST(빠른 주문) · EASY(이해하기 쉬운 주문) · SELF(스스로 해결하는 주문)
- **P0** 메뉴 화면, 빠른 선택, 쉬운 설명, 옵션, 상황별 도움, 장바구니 수정, 모의 결제, 자체 메뉴 API
- **P1** 자연어 검색, 메뉴 AI Q&A, 취향 필터 / **P2** 음성, 다국어, 실시간 품절, 실제 POS·결제
- **제외** 모바일 사전 주문, 직원용 시스템, 실제 결제, 얼굴·연령 인식, 브랜드 리뉴얼
- **사용성 테스트** 숙련 3 + 비숙련 3명, 기존안 vs 개선안 교차 배치

## 2. UX/UI 개선 — 대기열 부담과 모호한 문구
- **Problem 01** 뒤에 기다리는 사람 때문에 탐색을 서두르고, 질문하기 어렵다
- **Problem 02** '먹고 가기'/'픽업하기' 같은 모호한 버튼·UX Writing
- **전략** SEE(한눈에 발견) · UNDERSTAND(직관적 이해) · DECIDE(확신 있는 선택)
- **반영**
  - 주문 시작: "어디에서 드시나요?" — 매장에서 먹기 / 포장하기 동일 위계, 주문 확인에서도 변경 가능
  - 메뉴: 주요 메뉴, 카테고리 유지, 취향 필터 6종, 한 줄 설명 카드, 하단 고정 장바구니
  - 옵션: 따뜻하게(HOT)/차갑게(ICE), 커피를 더 진하게, 더 달콤하게, 필수·선택 구분, "추가 옵션 없이 장바구니에 담기"
  - 공통: 카운트다운·대기 인원 표시 없음, 이전 화면에서도 주문 유지, 도움말 닫으면 복귀
- **제외** 기본 플로우의 AI 챗봇·긴 자연어 입력

## 3. 쿠폰·결제 경험
- **Problem 03** 쿠폰·결제 수단을 결제 단계에서야 사용 불가로 알게 되어 주문이 중단됨
- **Solution 01** 시작 화면의 선택적 '쿠폰·결제 수단 미리 확인' (주문 단계 증가 없음), 쿠폰 종류별 조건·방법, 불가 시 사유·대체 방법, 확인 불가 쿠폰은 직원 안내
- **Solution 02** 할인 쿠폰·상품 교환권·금액권·결제 수단 구분, 지원되는 수단만 활성화, 결제 전 할인 금액과 최종 금액 표시, "금액 + 결제하기" 버튼
- **Solution 03** 실패 시 장바구니 유지, 원인·해결 방법 안내, 다른 쿠폰·다른 수단·주문 수정 제공, 승인 불확실 시 중복 결제 방지, 직원 지원 안내
- **화면** 쿠폰 확인 · 종류·방법 안내 · 적용 성공 · 적용 불가 · 수단 선택 · 방법 안내 · 실패 복구 · 승인 확인 중 · 완료

## 기대 효과 (검증 전 가설)
주문 시작 혼란·탐색 시간·불필요한 조작 감소, 심리적 압박 완화, 쿠폰 불가로 인한 재주문 감소, 결제 오류 자체 해결률 향상, 직원 도움 요청 감소, 독립 주문 완료율 향상.
