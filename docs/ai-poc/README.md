# AI Lab / Gemini API PoC

실제 Gemini API로 아래 **세 가지만** 확인하는 실험입니다. 최종 제품 개발이 아니고, 기존 키오스크 흐름은 바꾸지 않습니다. 실험 브랜치 `experiment/ai-poc`에서만 진행하며 `main`에는 병합하지 않습니다.

> 비공식 프로젝트입니다. 메뉴·가격은 테스트 데이터입니다.

1. 마이크로 한국어를 말하면 글자로 인식되는가
2. Gemini가 자연어 주문을 메뉴·수량·온도·옵션으로 분석하는가
3. 기존 메뉴 데이터를 바탕으로 자연어 메뉴 추천을 하는가

## 주소

| 주소 | 내용 |
|---|---|
| **`/ai-test.html`** | 이번 실험의 테스트 페이지. 입력창, 마이크 버튼, 결과 영역만 있음 |
| `/ai-lab.html` | 보존한 전체 버전(탭 구조, 모델 선택, 임시 장바구니). 지금은 쓰지 않음 |
| `/?ailab=1` | 보존한 키오스크 연동(AI Lab 버튼 + 오버레이). **기본은 꺼져 있음**, 주소에 `?ailab=1`을 붙일 때만 보임 |

배포 주소는 기존 Render 서비스 `https://hk06-uxpresso.onrender.com/`를 그대로 씁니다(새 서비스 없음).

## Render 설정 (직접 설정 필요)

1. Service → Settings → Build & Deploy → **Branch**를 `experiment/ai-poc`으로 하고, **Auto-Deploy**를 `On Commit`으로 둡니다. Auto-Deploy가 꺼져 있으면 새 커밋이 배포되지 않아 옛 화면이 계속 보입니다.
2. Environment에 환경변수를 설정합니다 (값은 Render 화면에만 입력).
3. Manual Deploy → **Deploy latest commit** 후 Events에서 배포된 커밋을 확인합니다.

| 이름 | 필수 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | 예 | Gemini API 키. 코드는 이 이름을 읽습니다 (`GOOGLE_API_KEY`도 인식) |
| `GEMINI_MODEL` | 아니요 | 모델을 한 개로 고정. 비우면 아래 "모델 선택"의 자동 순서를 씀 |
| `AI_LAB_TOKEN` | 권장 | 설정하면 모든 `POST /api/ai/*`에 이 토큰이 필요함 (테스트 페이지 위쪽 입력칸). 공개 주소의 무단 호출을 막음 |
| `AI_HOURLY_CAP` | 아니요 | 모든 방문자 합계 시간당 Gemini 요청 한도 (기본 120) |
| `AI_LAB_ENABLED` | 아니요 | `false`면 AI Lab API 전체가 꺼짐 (기존 키오스크는 영향 없음) |

키 값은 서버 환경변수로만 쓰이고 응답·로그·화면·GitHub 어디에도 나오지 않습니다. 키를 채팅·스크린샷 등에 올린 적이 있다면 Google AI Studio에서 폐기하고 새 키로 바꾸세요.

## 테스트 방법

1. `/ai-test.html`을 엽니다(토큰을 설정했다면 입력). 위쪽에 `GEMINI_API_KEY: 설정됨`이 보여야 합니다.
2. **`API 연결 테스트`**: 실제 Gemini를 한 번 호출합니다. 성공하면 모델·응답 시간·재시도 횟수가, 실패하면 원인과 해결 방법이 나옵니다.
3. **음성 인식**: `🎤 말하기`를 누르고 한국어로 말합니다(Chrome·Edge, HTTPS). 말하는 동안 중간 글자가 보이고, 끝나면 입력창에 글자가 들어갑니다. 글자를 고쳐도 됩니다. 이 단계의 성공은 "음성 인식 성공"으로 **따로** 표시됩니다.
4. **주문 분석**: 입력창 문장으로 `주문 분석`. 예시: `아아 하나` / `뜨아 두 잔` / `아아 하나랑 카페라떼 뜨거운 거` / `아아 두 개 중 하나만 샷 추가` / `아메리카노 하나`(온도를 되묻는 것이 정상)
5. **메뉴 추천**: `메뉴 추천`. 예시: `달달한 거 추천해 줘` / `3,000원 이하 음료 추천해 줘` / `추운데 따뜻한 음료 추천해 줘` / `카페인 없는 음료 추천해 줘`(영양 정보는 확인할 수 없다고 안내하는 것이 정상)

결과 아래에 모델·재시도 횟수·모델 변경 여부·총 응답 시간·Google 요청 횟수가 표시되고, 모델이 만든 JSON(서버 검증 전)과 서버 검증 후 JSON을 펼쳐 볼 수 있습니다.

## 동작 규칙

### 주문 분석 (`POST /api/ai/order`)
- Gemini는 문장을 JSON(`intent`, `items[{menuId, temperature, qty, options}]`)으로만 바꿉니다. 가격은 요청하지 않습니다.
- **서버가 `data/menus.json`으로 전부 다시 검증**합니다: 메뉴 id, 제공 온도, 수량(1~10 정수), 옵션 그룹·선택지, `onlyTemp` 규칙. **가격은 서버가 메뉴 데이터로 계산**합니다(모델이 보낸 가격은 무시).
- 온도를 말하지 않았고 HOT/ICE가 모두 가능하면 추측하지 않고 되묻습니다. 없는 메뉴·옵션이 하나라도 있으면 **주문 전체를 거부**하고, 옵션을 조용히 버리지도 않습니다.

### 메뉴 추천 (`POST /api/ai/recommend`)
- Gemini는 메뉴 목록 안에서 최대 3개를 고르고 이유를 적습니다. 서버가 다시 확인합니다: 없는 메뉴 제외, 가격 조건(모델이 읽은 값과 문장에서 서버가 직접 읽은 값 중 **낮은 값** 적용), 따뜻한/차가운 음료 조건. 이름·가격·태그·설명은 모델이 아니라 메뉴 데이터에서 가져옵니다.
- 영양·칼로리·당류·알레르기는 데이터가 없어서(`null`) 추측하지 않고 "확인할 수 없어요"로 안내합니다. 조건에 맞는 메뉴가 없으면 지어내지 않고 다른 조건을 제안합니다.

### 모델 선택
- **자동 순서(기본)**: 주문 분석은 단순한 구조화 작업이라 **경량·검증된 모델을 먼저** 씁니다: `gemini-2.5-flash-lite` → `gemini-2.5-flash` → `gemini-flash-lite-latest` → `gemini-flash-latest`. **버전 번호가 높다고 먼저 쓰지 않습니다.** 새 버전·preview 모델은 그 뒤에만 후보가 됩니다. (실제 배포에서 가장 높은 버전의 자동 선택 모델이 `503 UNAVAILABLE`이었던 일이 있었습니다.)
- 경량 모델이 한국어 주문을 얼마나 정확히 이해하는지는 **아직 검증되지 않았습니다.** 정확도·속도를 비교하려면 `/ai-lab.html`의 "모델 점검·비교" 서버 API(`/api/ai/models`, `/probe`, `/bench`)를 쓰거나, Render `GEMINI_MODEL`로 모델을 바꿔 가며 같은 문장을 시험하세요.

### 재시도와 모델 변경 (실제 API 오류, Mock으로 대신하지 않음)
| 상황 | 동작 |
|---|---|
| 500/502/503/504 | 같은 모델로 0.6초 쉬고 **1회 재시도** |
| 재시도에도 실패, 시간 초과, 404, 429 | **다음 모델로 변경** (자동 모드일 때) |
| 400/401/403 | **즉시 중단** (재시도·모델 변경으로 해결되지 않음) |
| 상한 | 한 요청당 모델 최대 3개, Google 요청 **최대 5회**, 대기 합계 3초 미만 |
| 시간당 예산 | 재시도·모델 변경까지 **모든 Google 요청**이 `AI_HOURLY_CAP`에서 차감되고, 바닥나면 즉시 중단 |

실패하면 실패로 표시하고, 시도 내역(모델·재시도 여부·HTTP 상태)과 원인·해결 방법을 보여줍니다. 성공한 응답은 어느 모델이 답했는지, 모델이 바뀌었는지를 함께 보여줍니다.

| HTTP | 화면 안내 |
|---|---|
| 401 | 키가 인증되지 않음. Render의 `GEMINI_API_KEY`를 다시 복사·저장하고 재배포 |
| 403 | 권한 문제. 키 폐기 여부, API 사용 설정, IP·사이트 제한, 지역 제한 확인 |
| 429 | 사용 한도 초과. 잠시 후 재시도, 다른 모델, 사용량·요금제 확인 |
| 503 | 모델에 수요가 몰림(일시적). 짧게 재시도했고 필요하면 모델을 바꿨음. 잠시 후 재시도 |

### 공개 테스트 API 보호
같은 사이트에서 보낸 요청만 허용(다른 사이트의 브라우저 요청은 403) · 선택적 접근 토큰 · IP당 분당 제한(연결 4회, 주문·추천 각 10회) · 전체 시간당 한도 · 입력 120자·요청 본문 4KB 제한 · 끄기 스위치(`AI_LAB_ENABLED=false`).

## API

| 주소 | 설명 |
|---|---|
| `GET /api/ai/config` | 키 설정 여부(값 아님), 한도, 정책 |
| `POST /api/ai/check` | 실제 Gemini 연결 테스트 |
| `POST /api/ai/order` | `{text}` 주문 분석 (Mock 선택용 `mock:true`는 보존된 전체 버전에서만 씀) |
| `POST /api/ai/recommend` | `{text}` 메뉴 추천 |
| `GET /api/ai/models` · `POST /api/ai/probe` · `POST /api/ai/bench` | 모델 목록(Flash-Lite/Flash/Pro 분류), 호출 가능 점검, 주문 5문장 정확도·속도 1건 실행 (보존된 전체 버전용) |
| `GET /api/ai/status` | 연결 상태(60초 캐시) |

`order`·`recommend`·`check`는 선택 파라미터 `model`(모델 이름 또는 `auto`), `fallback`(`false`면 다른 모델로 바꾸지 않음)을 받습니다. 목록에 없는 모델 이름은 Google을 부르기 전에 거절합니다.

## 검증 상태

| 항목 | 상태 |
|---|---|
| 서버 검증·가격 계산(주문 33), 추천 검증(27), 재시도·모델 변경·상한·오류 안내(37) | 로컬 통과 — **Gemini·Google 응답은 가짜(스텁)** 라서 로직만 증명함 |
| 테스트 페이지 브라우저 흐름 45개(주문·추천·마이크 오류·503 재시도·전체 실패·키 오류) | 로컬 통과 — **가짜 Google·가짜 음성 인식기** 사용 |
| 실제 Render 서버에서 키 유효성·모델 목록 조회 | 확인함 (HTTP 200, 모델 49개). 이전 자동 선택 모델의 `generateContent`는 503 |
| **실제 Gemini의 주문 해석·추천 품질** | **미검증** (Render에서 직접 확인 필요) |
| **실제 마이크로 한국어 인식** | **미검증** — 이 환경에는 마이크가 없어 수동 테스트 필요 |
| 경량 모델의 주문 정확도 | **미검증** |

```bash
node scripts/ai-order-test.mjs       # 주문 검증·가격 (모델 응답은 스텁)
node scripts/ai-recommend-test.mjs   # 추천 검증 (모델 응답은 스텁)
node scripts/ai-model-test.mjs       # 모델 선택·재시도·대체·상한 (Google 응답은 가짜)
node --import ./scripts/fake-google.mjs server.js   # 가짜 Google로 서버를 띄워 화면 확인 (FAKE_MODE=ok|flaky|down|badkey|forbidden|quota)
GEMINI_API_KEY=... node scripts/gemini-check.mjs    # 실제 Gemini 호출 확인 (키 필요)
```

## 코드 구조

```
public/ai-test.html, ai-simple.js   이번 실험의 단순 테스트 페이지
public/ai-lab.html + ai-lab/*       보존: 탭 구조 전체 버전 (주문 / 음성·추천 자리 / 개발자)
public/app.js, style.css            보존: 키오스크 AI Lab 버튼·오버레이 (?ailab=1 일 때만)
lib/gemini.mjs                      Gemini REST 호출, 모델 선택, 재시도·대체, 예산 연동, 오류 안내
lib/ai-order.mjs, ai-recommend.mjs  프롬프트, 서버 검증, 가격 계산
lib/ai-routes.mjs, guard.mjs        /api/ai/* 라우트, 보호 장치
server.js                           /api/ai/ 요청을 lib/ai-routes.mjs로 넘기는 2줄만 추가
```

보존한 키오스크 연동은 이번 실험에서 더 발전시키지 않습니다. 검증된 기능만 디자인·프로토타입 확정 뒤에 선별해서 통합합니다.
