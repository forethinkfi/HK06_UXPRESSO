# 01. 프로젝트 개요 (Overview)

## 1.1 프로젝트 배경

메가MGC커피는 다양한 메뉴와 옵션을 제공하며, 다양한 연령층과 디지털 숙련도를 가진 고객이 이용하는 커피 브랜드이다.

출근 시간과 점심시간 등 주문이 집중되는 피크타임에는 직원이 음료 제조와 고객 응대를 동시에 수행해야 한다.

특히 직원의 제조 업무가 집중되는 상황에서는 키오스크 이용에 어려움을 겪는 고객에게 즉각적인 도움을 제공하기 어려울 수 있다.

고객이 메뉴 탐색, 옵션 이해, 주문 방법 등의 어려움을 스스로 해결하지 못할 경우 주문 지연과 심리적 부담이 발생하며, 이는 뒤에 기다리는 고객의 대기 경험과 직원의 업무 부담에도 영향을 미칠 수 있다.

이에 고객의 독립적인 주문 경험을 지원하는 키오스크 UX/UI를 설계하여 고객 편의성과 매장의 주문 처리 효율을 함께 개선하고자 한다.

## 1.2 프로젝트 비전

기존의 주문을 접수하는 키오스크에서 고객의 주문을 도와주는 키오스크로 전환한다.

## 1.3 핵심 디자인 가치

- **FAST:** 원하는 메뉴를 불필요한 조작 없이 빠르게 주문한다.
- **EASY:** 메뉴와 옵션을 직관적으로 이해하고 선택한다.
- **SELF:** 직원의 도움 없이 주문 과정의 어려움을 스스로 해결한다.

# 02. 문제 정의 (Problem Definition)

## 2.1 핵심 문제

**직원의 고객 응대가 제한되는 피크타임에 고객이 키오스크 주문 과정에서 발생하는 어려움을 스스로 해결하지 못하면, 고객의 주문 지연과 직원의 업무 부담이 동시에 발생할 수 있다.**

## 2.2 문제 발견 배경

프로젝트의 출발점은 메가MGC커피 직원이 음료 제조 업무로 인해 고객에게 충분한 응대를 제공하기 어려운 경우가 있다는 정성적 제보이다.

키오스크는 직원의 주문 접수 업무를 대체하지만, 고객이 키오스크를 사용하는 과정에서 발생하는 어려움까지 충분히 해결하지 못한다면 직원의 추가적인 개입이 필요해질 수 있다.

이러한 문제는 주문이 집중되는 피크타임에 더욱 중요하게 작용할 가능성이 있다.

## 2.3 세부 문제 가설

| ID | 문제 | 원인 가설 | 영향 |
|---|---|---|---|
| P-01 | 메뉴 탐색의 어려움 | 상품 중심의 카테고리와 생소한 메뉴명 | 탐색 시간 증가 |
| P-02 | 메뉴 및 옵션 이해 부족 | 설명 부족 및 어려운 용어 | 직원 문의 및 주문 오류 |
| P-03 | 불필요한 주문 조작 | 반복적인 선택 및 화면 전환 | 키오스크 점유 시간 증가 |
| P-04 | 주문 문제의 자체 해결 어려움 | 상황별 도움 및 오류 복구 기능 부족 | 직원 도움 의존 |
| P-05 | 즉각적인 고객 응대의 어려움 | 피크타임 음료 제조 업무 집중 | 고객 주문 지연 |
| P-06 | 주문 중 심리적 부담 | 뒤에 기다리는 고객의 존재 | 성급한 선택 및 주문 포기 가능성 |

## 2.4 문제 발생 구조

피크타임 주문 집중

→ 직원의 음료 제조 업무 증가

→ 고객 응대 여력 감소

→ 키오스크 이용 중 발생한 어려움 미해결

→ 주문 지연 및 추가적인 도움 요청

→ 고객 대기 경험 및 직원 업무 부담 악화 가능성

## 2.5 문제 선정 근거 및 검증 상태

| 근거 | 확보 상태 | 검증 방법 |
|---|---|---|
| 직원의 피크타임 응대 어려움 | 초기 정성적 제보 | 직원 인터뷰 |
| 기존 키오스크 탐색 구조 | 참고 자료 확보, 세부 분석 필요 | 키오스크 탐방 자료 및 UI Audit |
| 메뉴 및 옵션 이해의 어려움 | 가설 | 고객 관찰 및 인터뷰 |
| 반복적인 주문 지원 업무 | 가설 | 직원 인터뷰 및 응대 유형 기록 |
| 주문 지연과 대기열의 관계 | 가설 | 피크타임 현장 관찰 |

현재 실제 매장의 운영 데이터 및 충분한 사용자 조사 결과는 확보되지 않았다. 따라서 문제 정의는 현장 리서치를 통해 검증하고 수정한다.

# 03. 프로젝트 목표 (Goals)

## 3.1 핵심 목표

직원의 즉각적인 도움 없이도 다양한 고객이 스스로 쉽고 정확하게 주문할 수 있는 키오스크 경험을 설계한다.

## 3.2 사용자 목표

- 원하는 메뉴를 빠르게 찾을 수 있다.
- 메뉴와 옵션의 의미를 쉽게 이해할 수 있다.
- 불필요한 조작 없이 주문할 수 있다.
- 주문 과정에서 발생한 어려움을 스스로 해결할 수 있다.
- 잘못 선택한 메뉴와 옵션을 쉽게 수정할 수 있다.

## 3.3 비즈니스 목표

- 반복적인 키오스크 사용 지원 업무 감소
- 직원의 음료 제조 업무 중단 최소화
- 키오스크 주문 처리 효율 향상
- 피크타임 주문 병목 완화 가능성 확보
- 다양한 고객층의 서비스 접근성 향상

## 3.4 HMW (How Might We?)

**어떻게 하면 직원이 음료 제조에 집중해야 하는 바쁜 순간에도 고객이 스스로 막힘 없이 주문할 수 있을까?**

## 3.5 핵심 가설

메뉴 탐색과 옵션 선택 과정을 직관적으로 개선하고, 필요한 순간에 상황별 주문 도움을 제공하면 고객의 독립적인 주문 완료율이 향상되고 직원의 반복적인 주문 지원 요청이 감소할 것이다.

단, 기존 숙련 고객의 주문 효율이 저하되지 않아야 한다.

# 04. 타깃 사용자 (Target Users)

사용자를 연령이 아닌 주문 목적과 행동 특성, 디지털 숙련도를 기준으로 구분한다.

## Type A. 목적형 고객

**특징**

- 원하는 메뉴가 이미 정해져 있다.
- 동일한 메뉴를 반복적으로 구매한다.
- 주문 속도를 중요하게 생각한다.

**Pain Point**

- 원하는 메뉴를 찾기 위한 반복적인 탐색
- 불필요한 옵션 선택 및 화면 전환

**Needs**

원하는 메뉴를 빠르고 정확하게 주문하고 싶다.

## Type B. 탐색형 고객

**특징**

- 주문할 메뉴를 결정하지 못했다.
- 메뉴의 맛과 특징을 비교하고 싶다.
- 정확한 메뉴명을 모를 수 있다.

**Pain Point**

- 다양한 메뉴로 인한 선택 부담
- 메뉴명만으로 음료의 특징을 이해하기 어려움
- 직원에게 메뉴를 질문하기 어려운 상황

**Needs**

충분한 정보를 바탕으로 자신에게 맞는 메뉴를 선택하고 싶다.

## Type C. 주문 지원이 필요한 고객

**특징**

- 키오스크 사용 경험이 상대적으로 적다.
- 생소한 용어와 조작 방식에 어려움을 느낀다.
- 주문 실수에 대한 불안감이 있다.

**Pain Point**

- 다음 행동을 이해하기 어려움
- 주문 오류를 스스로 해결하기 어려움
- 직원의 도움을 즉시 받기 어려움

**Needs**

다른 사람의 도움 없이 안심하고 주문하고 싶다.

## Secondary User. 매장 직원

**특징**

- 피크타임에 음료 제조와 고객 응대를 병행한다.

**Pain Point 가설**

- 반복적인 메뉴 및 주문 관련 문의
- 음료 제조 중 발생하는 고객 지원 요청

**Needs**

고객이 기본적인 주문 문제를 스스로 해결하여 음료 제조 업무에 집중할 수 있기를 원한다.

※ 사용자 유형은 고정된 분류가 아니며 한 고객이 상황에 따라 여러 유형에 해당할 수 있다.

5. 고객이 키오스크에서 직접 해결했으면 하는 문제가 있나요?

1. 평소 카페 키오스크를 얼마나 자주 이용하시나요?
2. 주문 과정에서 가장 오래 걸리는 단계는 무엇인가요?
3. 메뉴나 옵션의 의미를 몰라 어려웠던 경험이 있나요?
4. 직원에게 도움을 요청했던 경험이 있나요?
5. 도움을 요청하지 못해 주문을 변경하거나 포기한 경험이 있나요?
6. 뒤에 사람이 기다릴 때 어떤 부담을 느끼나요?

## 5.5 문제 우선순위 선정

다음 기준을 활용하여 개선할 문제를 선정한다.

- 문제 발생 빈도
- 고객 주문 경험에 미치는 영향
- 직원 업무에 미치는 영향
- 자체 해결 가능성
- 2일 내 구현 및 검증 가능성

리서치 결과에 따라 가장 영향도가 높은 문제 1~2개를 핵심 구현 대상으로 확정한다.

# 06. 최종 추천 개선 전략 (Solution Strategy)

## Solution 01. FAST — 빠른 주문

**문제**

원하는 메뉴가 정해진 고객에게 반복적인 메뉴 탐색과 옵션 선택이 발생할 수 있다.

**해결 방안**

- 첫 메뉴 화면에서 주요 메뉴 바로 선택
- 전체 메뉴 탐색 경로 유지
- 메뉴 카드 내 핵심 정보 제공
- 관련 옵션의 통합 배치
- 불필요한 화면 전환 최소화
- 장바구니에서 즉시 수량 및 옵션 수정

**기대 효과**

- 메뉴 탐색 시간 감소
- 주문 단계 및 터치 횟수 감소
- 키오스크 점유 시간 감소

## Solution 02. EASY — 이해하기 쉬운 주문

**문제**

메뉴명과 옵션의 의미를 이해하기 어려운 고객은 선택 과정에서 망설이거나 직원에게 도움을 요청할 수 있다.

**해결 방안**

- 카테고리와 취향별 필터를 함께 제공
- 메뉴의 맛과 특징을 쉬운 언어로 설명
- 자연어 기반 메뉴 검색 기능 제공
- 온도와 옵션의 의미를 직관적으로 표현
- 추가 금액 실시간 표시
- 필수 옵션과 선택 옵션 명확하게 구분

**API 활용**

자체 메뉴 데이터 API 및 OpenAI API를 활용한다.

**기대 효과**

- 메뉴 선택 부담 감소
- 메뉴 및 옵션 이해도 향상
- 반복적인 메뉴 문의 감소 가능성

## Solution 03. SELF — 스스로 해결하는 주문

**문제**

직원이 바쁜 상황에서 고객이 주문 중 발생한 어려움을 즉시 해결하지 못할 수 있다.

**해결 방안**

- 모든 주요 주문 단계에서 주문 도움 기능 제공
- 현재 화면과 관련된 상황별 도움말 제공
- 메뉴 관련 자주 묻는 질문 제공
- 메뉴 정보 기반 AI 질의응답
- 주문 오류의 원인과 해결 방법 안내
- 기존 주문 상태를 유지한 채 수정 및 복귀
- 자체 해결이 어려운 문제는 직원 지원으로 연결

**API 활용**

OpenAI API를 활용한 제한된 메뉴 정보 질의응답.

일반적인 주문 방법 및 오류 복구는 정형화된 도움말과 UI 개선으로 해결한다.

**기대 효과**

- 독립 주문 완료율 향상
- 직원 도움 요청 감소
- 주문 오류의 자체 해결률 향상
- 고객의 심리적 부담 완화

# 07. 핵심 디자인 원칙 (Design Principles)

## 7.1 공통 인터페이스

빠른 주문, 일반 주문, 쉬운 주문을 별도의 모드로 강제 구분하지 않는다.

모든 고객이 동일한 메뉴 화면에서 자신의 상황에 필요한 기능을 선택할 수 있도록 한다.

## 7.2 점진적 정보 공개

기본 화면에는 주문에 필요한 핵심 정보만 제공하고 상세 설명과 도움말은 필요한 순간에 확인할 수 있도록 한다.

## 7.3 독립적인 주문 지원

직원의 도움을 기다리지 않고 고객이 메뉴 정보, 옵션 설명, 주문 수정 방법을 확인할 수 있도록 한다.

## 7.4 오류 예방 및 복구

잘못된 선택을 예방하고 오류 발생 시 처음부터 주문을 다시 시작하지 않도록 한다.

## 7.5 포용적 디자인

연령이나 장애 여부에 따라 고객을 분리하지 않고 쉬운 언어, 충분한 터치 영역, 명확한 시각적 위계 및 접근성을 공통 UI에 적용한다.

## 7.6 기존 고객의 효율 유지

추가적인 안내 기능이 기존 숙련 고객의 주문 과정에 불필요한 단계를 만들지 않도록 한다.

# 09. 기능 요구사항 (Functional Requirements)

## FR-01. 공통 메뉴 화면

**우선순위: P0**

**사용자 스토리**

고객으로서 별도의 주문 모드를 선택하지 않고 원하는 메뉴를 바로 탐색하고 싶다.

**요구사항**

- 주요 메뉴와 전체 메뉴 카테고리를 제공한다.
- 메뉴명, 이미지, 가격을 명확하게 표시한다.
- 장바구니 및 주문 도움에 접근할 수 있어야 한다.
- 선택된 카테고리 상태를 명확하게 표시한다.

**완료 조건**

고객이 추가적인 모드 선택 없이 메뉴 탐색을 시작할 수 있다.

## FR-02. 빠른 메뉴 선택

**우선순위: P0**

**사용자 스토리**

원하는 메뉴가 정해진 고객으로서 여러 카테고리를 이동하지 않고 빠르게 주문하고 싶다.

**요구사항**

- 첫 메뉴 화면에서 주요 메뉴를 선택할 수 있다.
- 전체 메뉴 탐색 경로를 유지한다.
- 주요 메뉴 선택 후 옵션 선택 화면으로 이동한다.
- 실제 판매 데이터가 없는 경우 인기 순위라고 표시하지 않는다.

**완료 조건**

대표 주문 과업에서 기존안보다 메뉴 탐색 조작이 줄어든다.

## FR-03. 메뉴 상세 정보

**우선순위: P0**

**사용자 스토리**

메뉴에 익숙하지 않은 고객으로서 직원에게 질문하지 않고 음료의 특징을 알고 싶다.

**요구사항**

- 메뉴 이미지, 이름, 가격을 제공한다.
- 주요 특징을 이해하기 쉬운 문장으로 제공한다.
- 공식적으로 확인된 원재료 및 영양정보만 제공한다.
- 상세 설명은 선택적으로 확인할 수 있다.
- 정보가 확인되지 않은 경우 이를 명시한다.

**완료 조건**

고객이 메뉴의 기본적인 특징을 화면에서 확인할 수 있다.

## FR-04. 옵션 선택

**우선순위: P0**

**사용자 스토리**

고객으로서 옵션의 의미와 추가 금액을 이해하고 정확하게 주문하고 싶다.

**요구사항**

- 관련 옵션을 한 화면 또는 이해하기 쉬운 단위로 구성한다.
- 필수 옵션과 선택 옵션을 구분한다.
- HOT/ICE에 쉬운 우리말을 병기한다.
- 생소한 옵션 용어에 설명을 제공한다.
- 옵션 선택에 따른 추가 금액을 즉시 반영한다.
- 선택 가능한 옵션만 활성화한다.
- 색상 외에 체크 표시 및 텍스트로 선택 상태를 전달한다.

**완료 조건**

고객이 선택한 메뉴, 옵션 및 최종 가격을 확인한 후 장바구니에 담을 수 있다.

## FR-05. 상황별 주문 도움

**우선순위: P0**

**사용자 스토리**

주문에 어려움을 겪는 고객으로서 직원을 기다리지 않고 현재 단계의 문제를 해결하고 싶다.

**요구사항**

- 주요 주문 화면에 일관된 도움 진입점을 제공한다.
- 현재 주문 단계에 맞는 도움말을 표시한다.
- 메뉴 탐색, 옵션 설명, 수량 변경, 주문 수정 등의 도움말을 제공한다.
- 도움말을 닫아도 기존 주문 상태를 유지한다.
- 자체 해결이 어려운 경우 직원에게 도움을 요청하도록 안내한다.

**완료 조건**

고객이 기존 주문 정보를 잃지 않고 도움말을 확인한 후 주문을 이어갈 수 있다.

## FR-06. 장바구니 및 주문 수정

**우선순위: P0**

**사용자 스토리**

잘못된 메뉴나 옵션을 선택한 고객으로서 주문을 처음부터 다시 시작하지 않고 수정하고 싶다.

**요구사항**

- 메뉴명, 옵션, 수량 및 가격을 표시한다.
- 수량 변경과 상품 삭제를 지원한다.
- 선택한 옵션을 수정할 수 있다.
- 변경 사항을 총액에 즉시 반영한다.
- 전체 주문 취소 시 확인 절차를 제공한다.

**완료 조건**

고객이 기존 장바구니를 유지한 채 주문 오류를 수정할 수 있다.

## FR-07. 주문 확인 및 완료

**우선순위: P0**

**요구사항**

- 결제 전 전체 주문 내역을 표시한다.
- 매장 이용 및 포장 여부를 확인할 수 있다.
- 최종 결제 금액을 명확하게 표시한다.
- 모의 결제 과정을 제공한다.
- 주문 완료 후 주문번호와 픽업 방법을 안내한다.
- 주문 종료 후 이전 고객의 주문 정보를 초기화한다.

**완료 조건**

고객이 정확한 주문 내역을 확인하고 모의 결제를 완료할 수 있다.

## FR-08. 자체 메뉴 데이터 API

**우선순위: P0**

**요구사항**

- 등록된 메뉴 목록을 조회할 수 있다.
- 메뉴별 상세 정보와 옵션을 조회할 수 있다.
- 카테고리별 메뉴 조회를 지원한다.
- API 연결 실패 시 기본 메뉴 데이터로 주문을 이어갈 수 있다.

**완료 조건**

프로토타입에서 API 요청을 통해 메뉴 정보를 불러와 화면에 표시한다.

## FR-09. 자연어 메뉴 검색

**우선순위: P1**

**사용자 스토리**

정확한 메뉴명을 모르는 고객으로서 원하는 맛과 특징을 일상적인 언어로 입력하고 메뉴를 찾고 싶다.

**요구사항**

- 자연어 입력을 지원한다.
- 등록된 메뉴 데이터 안에서만 검색 결과를 제공한다.
- 결과를 선택 가능한 메뉴 카드로 표시한다.
- 결과가 없을 경우 검색 조건 변경을 안내한다.
- API 지연 및 오류 시 일반 메뉴 탐색을 제공한다.
- 고객의 확인 없이 주문을 확정하지 않는다.

**완료 조건**

자연어 요청에 맞는 등록 메뉴를 찾아 선택할 수 있다.

## FR-10. 메뉴 정보 기반 AI 질의응답

**우선순위: P1**

**사용자 스토리**

메뉴에 대해 궁금한 고객으로서 직원에게 질문하지 않고 기본적인 정보를 확인하고 싶다.

**요구사항**

- 등록된 메뉴 정보에 기반해 답변한다.
- 자주 묻는 질문을 버튼 형태로 제공한다.
- 답변은 짧고 이해하기 쉬운 문장으로 구성한다.
- 가격 및 옵션 정보를 임의로 생성하지 않는다.
- 확인되지 않은 정보는 모른다고 안내한다.
- 알레르기, 결제 장애 등 직원의 확인이 필요한 문제는 별도 지원을 안내한다.

**완료 조건**

고객이 검증된 메뉴 정보에 대한 기본적인 질문을 해결할 수 있다.

# 14. API 및 기술 요구사항 (Technical Requirements)

## 14.1 API 활용 목적

API는 단순한 기술적 차별점이 아니라 고객이 직원의 도움 없이 메뉴를 탐색하고 정보를 확인할 수 있도록 지원하는 수단으로 활용한다.

## 14.2 자체 메뉴 데이터 API

**우선순위: P0**

| Method | Endpoint | 기능 |
|---|---|---|
| GET | /api/menus | 전체 메뉴 조회 |
| GET | /api/menus/:id | 메뉴 상세 조회 |
| GET | /api/categories | 카테고리 조회 |
| GET | /api/menus?tags= | 메뉴 속성별 조회 |

위 Endpoint는 프로젝트 자체 API 설계 예시이며 메가MGC커피의 공식 API가 아니다.

## 14.3 OpenAI API

**우선순위: P1**

**활용 기능**

- 자연어 메뉴 검색
- 사용자 취향 기반 메뉴 탐색
- 메뉴 관련 기본 질의응답

**사용 예시**

입력: 커피 말고 달콤하고 차가운 음료를 찾고 있어요.

처리: 사용자 요청에서 음료 종류, 맛, 온도 등의 조건을 추출한다.

출력: 등록된 메뉴 데이터 중 조건에 맞는 메뉴 ID 목록을 반환한다.

키오스크는 반환된 ID를 기반으로 실제 등록 메뉴 카드와 가격을 표시한다.

## 14.4 API 처리 구조

키오스크 사용자 입력

→ 자체 서버 API

→ 메뉴 데이터 조회

→ OpenAI API를 통한 검색 조건 해석 또는 답변 생성

→ 등록된 메뉴 정보 검증

→ 키오스크 화면에 결과 표시

## 14.5 메뉴 데이터 구조

| 필드 | 설명 |
|---|---|
| id | 메뉴 고유 ID |
| name | 메뉴명 |
| category | 메뉴 카테고리 |
| price | 기본 가격 |
| image_url | 메뉴 이미지 |
| description | 메뉴 설명 |
| tags | 확인된 맛 및 특징 |
| temperature | 선택 가능한 온도 |
| options | 선택 가능한 옵션 |
| nutrition | 확인된 영양정보 |
| allergens | 확인된 알레르기 정보 |
| available | 테스트 환경의 주문 가능 여부 |
| source | 메뉴 정보 출처 |

## 14.6 기술 스택 제안

| 구분 | 기술 |
|---|---|
| UX/UI 디자인 | Figma |
| 프론트엔드 | React 또는 HTML/CSS/JavaScript |
| 메뉴 데이터 | JSON 또는 자체 데이터베이스 |
| 백엔드 | 경량 REST API 또는 BaaS |
| AI 검색 및 질의응답 | OpenAI API |
| 프로토타입 | 브라우저 기반 키오스크 화면 |

## 14.7 API 오류 및 안전 요구사항

- API 연결 실패 시 기본 메뉴 탐색으로 전환한다.
- AI 응답 지연 시 로딩 상태를 표시하고 취소할 수 있도록 한다.
- AI가 존재하지 않는 메뉴를 추천하지 않도록 한다.
- 가격, 옵션 및 재고는 AI 답변이 아닌 등록된 데이터를 기준으로 한다.
- 알레르기 및 영양정보를 임의로 생성하지 않는다.
- 고객의 개인정보 및 결제정보를 AI API로 전송하지 않는다.
- API 키를 클라이언트에 노출하지 않는다.

## 14.8 데이터 활용 제약

실제 메가MGC커피의 내부 주문 및 판매 데이터에 접근할 수 없으므로 공개된 메뉴 정보와 테스트 데이터를 활용한다.

가상 판매량, 인기 순위 및 주문 데이터를 실제 메가MGC커피 운영 데이터로 표현하지 않는다.

# 16. 성공 지표 (Success Metrics)

## 16.1 핵심 KPI

**독립 주문 완료율 (Independent Order Completion Rate)**

직원 또는 테스트 진행자의 도움 없이 주어진 주문 과업을 정확하게 완료한 비율.

독립 주문 완료율 = 도움 없이 정확하게 완료한 과업 수 ÷ 전체 시도 과업 수 × 100

키오스크 내부의 도움말이나 AI 기능을 활용하여 주문을 완료한 경우 독립 주문 성공으로 인정한다.

## 16.2 보조 KPI

| 지표 | 측정 방법 | 초기 목표 |
|---|---|---|
| 독립 주문 완료율 | 도움 없는 정확한 주문 성공 비율 | 기존 대비 향상 |
| 주문 완료 시간 | 동일 난이도 과업의 시간 비교 | 20% 감소 |
| 메뉴 탐색 시간 | 메뉴 선택까지 소요된 시간 | 20% 감소 |
| 도움 요청 횟수 | 외부 도움을 요청한 횟수 | 30% 감소 |
| 터치 횟수 | 과업 완료까지 조작 횟수 | 기존 대비 감소 |
| 주문 오류 | 잘못된 메뉴 및 옵션 선택 | 기존 대비 감소 |
| 오류 복구 성공률 | 외부 도움 없이 오류를 수정한 비율 | 기존 대비 향상 |
| 심리적 부담 | 과업 종료 후 5점 척도 | 기존 대비 감소 |

## 16.3 가드레일 지표

비숙련 고객의 사용성을 개선하면서 숙련 고객의 주문 경험이 악화되지 않아야 한다.

- 숙련 고객의 주문 완료 시간 악화 방지
- 주문 정확도 저하 방지
- AI 기능으로 인한 필수 주문 단계 증가 방지
- 도움말로 인한 화면 복잡도 증가 방지

## 16.4 목표 수치의 해석

제시된 수치는 프로젝트의 초기 목표이며 실제 개선 성과가 아니다.

기존 키오스크의 기준값을 확보한 후 현실적인 목표를 확정한다.

# 17. 사용성 테스트 (Usability Test)

## 17.1 테스트 목적

개선된 키오스크가 고객의 독립적인 주문을 지원하고 주문 효율을 개선하는지 확인한다.

## 17.2 테스트 대상

- 키오스크 숙련 사용자 3명
- 키오스크 비숙련 사용자 3명
- 총 6명 권장

숙련도는 연령이 아닌 키오스크 이용 빈도와 독립적인 주문 경험을 기준으로 구분한다.

## 17.3 테스트 과업

| ID | 과업 | 검증 목적 |
|---|---|---|
| T-01 | 아이스 아메리카노 1잔 포장 주문 | 빠른 주문 |
| T-02 | 커피가 아닌 달콤하고 차가운 음료 주문 | 메뉴 탐색 |
| T-03 | 카페라떼에 샷을 추가하여 주문 | 옵션 이해 |
| T-04 | 잘못 선택한 메뉴의 온도 및 수량 수정 | 오류 복구 |
| T-05 | 생소한 옵션의 의미를 확인하고 주문 | 독립 주문 도움 |

2일 내 테스트 시간을 고려하여 핵심 문제에 해당하는 과업 3개를 우선 진행한다.

## 17.4 테스트 방식

1. 참여자의 키오스크 이용 경험을 확인한다.
2. 기존 키오스크를 재현한 프로토타입으로 과업을 수행한다.
3. 개선된 프로토타입으로 동일 난이도의 과업을 수행한다.
4. 주문 시간, 터치 횟수, 오류 및 도움 요청을 기록한다.
5. 과업 종료 후 심리적 부담과 편의성을 평가한다.
6. 사용자 행동과 발언을 바탕으로 추가 개선점을 도출한다.

학습 효과를 줄이기 위해 기존안과 개선안의 테스트 순서를 참여자별로 교차 배치한다.

화면 크기, 메뉴 구성, 결제 조건 및 과업 난이도를 가능한 한 동일하게 유지한다.

## 17.5 정성 데이터 기록

- 메뉴 탐색 중 망설인 이유
- 이해하지 못한 옵션 용어
- 도움말을 발견하거나 발견하지 못한 이유
- 주문 오류가 발생한 상황
- 기존안과 개선안에서 나타난 행동 차이
- 사용자가 직접 설명한 편의성 및 부담감

## 17.6 테스트 결과 해석

소규모 사용성 테스트 결과는 탐색적 검증으로 해석한다.

프로토타입에서 확인된 주문 효율 개선을 실제 매장의 매출 증가나 직원 업무시간 감소로 확정하지 않는다.

# 21. 프로젝트 완료 기준 (Definition of Done)

- 실제 키오스크 분석을 기반으로 핵심 문제를 정의하였다.
- 기존 브랜드 정체성을 유지한 개선 UI를 제작하였다.
- 메뉴 선택부터 모의 결제까지 주문을 완료할 수 있다.
- 고객이 메뉴와 옵션 정보를 스스로 확인할 수 있다.
- 주문 중 도움말을 확인하고 기존 주문 상태로 복귀할 수 있다.
- 고객이 잘못 선택한 메뉴와 옵션을 직접 수정할 수 있다.
- 최소 하나의 API 연동 기능을 실제로 시연할 수 있다.
- 기존안과 개선안의 비교 사용성 테스트를 진행하였다.
- 개선 효과와 한계를 실제 테스트 결과를 기반으로 설명할 수 있다.
